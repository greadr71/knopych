# «Кнопыч» — приложение-мост (v0.51)

Приложение на ГУ. Включает подогревы командами Aptiv, теми же, что шлёт штатный экран
климата.

## Что умеет
- **Команды подогревов**: сиденья водителя/пассажира (0–3), руль, лобовое — настоящими командами Aptiv.
- **Экран**: две вкладки — «Панель» и «Сценарии». Панель нарисована по модели `v2/modeling/` (ручка Ø28, шесть кейкапов 17 мм в блоке 3×2), состояния на ней нет: у кнопок v2 нет светодиодов. Подробности в разделе «Экран панели».
- **Автосценарии**: «Подогрев в холод» и «Тема при включении» (см. ниже).
- **Тема ГУ**: `theme 1..4`, `theme next` через службу `com.aptiv.thememanager`. Записи настройки мало: служба пишет `def_aptiv_config_current_theme_id`, SystemUI разносит пакет темы в `app_aptiv_config_current_theme_package_name`, по нему приложения грузят skin. Команда ждёт совпадения обоих и говорит прямо, если настройка записалась, а экран остался прежним. Сценарий «Тема при включении» ставит тему через 30 с после ACC/ON, затем повторяет раз в минуту до подтверждения.
- **Панель ESP по USB** (`EspLink`, ГУ в usb mode → host): плата находится сама (VID 303a). Кнопки по кейкапам: 1, 2, 3 — пресеты положения сиденья водителя (**удержание 1,5 с — сохранить текущее положение в слот**), 4 — подогрев водителя (выкл → 3 → 2 → 1; **удержание 1,5 с — яркость ГУ в другой край**), 5 — лобовое, 6 — подогрев пассажира. Руль и автосценарий с панели убраны (команды остались). Панель только шлёт события: состояние машины и обратную связь держит мост, подтверждение удержания — плашкой. Светодиодов у прошивки v1.0 нет.
- **Панель ESP по Bluetooth** (`BleLink`, v0.14): коннект **по MAC** из настройки `ble_mac` (без скана, поэтому для коннекта по MAC `ACCESS_FINE_LOCATION` не нужен; он объявлен в манифесте только для `ble_scan`), notify на кнопках, `autoConnect` + повтор из тика сервиса. Если autoConnect 20 с молчит (после перезагрузки ГУ бывает: объект есть, колбэков нет), соединение закрывается и попытка повторяется — иначе BLE оставался мёртвым до перезапуска приложения. USB и BLE живут одновременно: нажатие берётся из того канала, где оно пришло. По BLE нет `ping`/`!pong` и `!hello` — живость канала = состояние GATT, смотреть `ble`. **В машине проверено 15 ноября:** стек Aptiv GATT-коннект пускает, notify работает; нажатие по BLE доходит при выдернутом USB. Старый APK 0.48 ищет характеристику LEDS и с прошивкой v1.0 по BLE не соединится; новый APK работает и со старой.
- **Ручка панели**: громкость, а с открытым климатом температура и вентилятор. Подробности в разделе «Ручка панели».
- **Плашка поверх любого экрана (v0.49).** Кнопки 4/5/6 и автосценарий при включении показывают на 2,5 с плашку по центру: подогрев — три ступени, иконка сиденья (три стрелки, как на экране климата; у водителя зеркальная) и подпись «Водитель»/«Пассажир»; лобовое — иконка и «Включено»/«Выключено»; кнопки 1–3 — слоты сиденья: три кейкапа `kc_seat1..3` в ряд (130×104 dp, зазор 14), выбранный слот оранжевый, остальные притушены, подписи нет (удержание слота — тот же ряд с подписью «Слот N сохранён»/«не сохранён»). Включённое оранжевое (#FF9A4D), выключенное притушено альфой. Окно нефокусируемое и тапа не перехватывает — нижний экран (климат, навигация) не перерисовывается и не уходит в паузу. Рамка — из активной темы ГУ, подробности в разделе «Плашка». Отладка: `popup …`, `popup preset N [saved|failed]`, `popup sizes`.
- **Яркость ГУ**: `brightness` — текущая, `brightness 1..10`, `brightness toggle`. Удержание кнопки 4 (1,5 с): сейчас максимум → минимум, иначе (в том числе «между») → максимум. Пишем vehicle function 242 — ту же, что штатный ползунок в шторке ГУ (диапазон 1..10); Android-настройка `screen_brightness` не используется, панель GWM её не читает. Режим автосвета машины читаем через `AptivCarVariable.getDayNightMode()` (property `0x21703004`, байт 1: 1 день, 2 ночь). VHAL `0x11200407` из журнала убран: polling там всегда 0, а событий HAL не шлёт (см. [docs/gwm-api.md](../docs/gwm-api.md)).

- **Автояркость по ночи**: третья карточка в «СЦЕНАРИЯХ» и команда `auto_bright on/off` (по умолчанию выкл.). При смене дня/ночи мост ставит яркость 10 днём и 1 ночью и повторяет запись через 2 с (ГУ перебивает яркость сразу после смены режима). Ночью считает только вне окна **08:00–16:00**: автосвет включает фары и в пасмурный день, и без окна экран гас бы среди дня (`DAY_FROM_HOUR`/`DAY_TO_HOUR`). Плюс гистерезис 3 мин (`DAY_HOLD_MS`): в ночь уходим сразу, а обратно в 10 — только если автосвет продержал «день» 3 минуты, иначе дребезг автосвета тряс бы экран. Датчика освещённости в машине нет — это лучшее из доступного. Режим «неизвестно» и OFF/ACC не трогаются.
- **Связь с Mac по Wi-Fi** (`NetServer`, порт 5577, токен с экрана). Обновление — через adb по Wi-Fi (порт 5555, включается один раз по кабелю — см. «Установка моста»): из приложения прошивка GWM ставить пакеты не даёт (whitelist).
- Лобовое при незаведённом двигателе (`state=21`) не нажимает, а ждёт события; нажатие не чаще раза в 30 с.
- Отступы экрана под панели GWM: `ui_pad <слева> <сверху>` (пиксели).

```
Mac / adb / MacroDroid / ESP  ──команда──▶  мост  ──API Aptiv──▶  подогревы
                                              │
                                              └─ автосценарий: запуск двигателя + за бортом < 5 °C
```

### Экран панели

Экран — две вкладки: «Панель» и «Сценарии». Панель — вкладка на всё содержимое, лицо
короба нарисовано по модели из `v2/modeling/`: 90 : 53,3, ручка Ø28 слева, шесть
кейкапов 17 мм шагом 19 в блоке 3×2 справа (верх 1·2·3, низ 4·5·6), шесть векторных
иконок. Вид вписывается по меньшей стороне поля с воздухом 24 dp и центрируется,
пропорция не ломается. Подписей под кейкапами нет, назначение видно по нажатию.

В шапке между «КНОПЫЧ» и «ОТЛАДКА» идёт подсказка «Коснитесь кнопки…» одной строкой
22 sp. Вторая вкладка — сценарии крупно: названия 36 sp, выжимки 28 sp. Состояние
машины, «Связь» и «Журнал» живут в отладке: кнопка «Отладка» в шапке, состояние
помнится. Шрифты: Press Start 2P для подписи и чисел, IBM Plex Sans для текста
(OFL-лицензии в `res/raw/`); иконка в той же палитре.

Индикации состояния на панели нет: у кнопок v2 нет светодиодов, поэтому экран о машине
молчит. Что включено, видно в карточке кнопки и в строках сценариев; сработавшее
удержание подтверждается плашкой, а не миганием.

Тап по кейкапу открывает карточку этой кнопки: 1–3 поставить или сохранить пресет, 4
уровень подогрева и яркость ГУ, 5 лобовое, 6 пассажир. В карточке два действия,
«нажатие» и «удержание 1,5 с»; возврат — шапка «← Назад». Строка сценария со стрелкой
открывает подстраницу с настройками, выход по «Назад». Как устроен экран целиком —
[../DESIGN.md](../DESIGN.md).

### Ручка панели: климат и громкость

Режим работает, пока открыт экран климата. С v0.30 ручка управляет температурой, с
v0.34 она ставится абсолютным значением. Экран климата сам сообщает
`VISIBLE`/`INVISIBLE`, поэтому режим включается и тогда, когда климат открыли штатной
кнопкой или через меню.

Климат закрыт: вращение — громкость, нажатие кнопки открывает экран климата. Климат
открыт: вращение задаёт температуру водительской зоны абсолютным значением
(`setHvacFunctionValue(38, °C×10)`), сразу за ним уходит кадр отпускания `38 = −10`,
как пишет штатная шкала; шаг ±0,5 °C. При выключенном режиме «2 зоны» машина двигает
обе температуры сама. Удержание кнопки ≥0,6 с вместе с вращением даёт вентилятор 1..7.
Короткое нажатие закрывает экран, но то нажатие, которым климат открыли, на отпускании
экран не закрывает. После закрытия 400 мс вращение игнорируется целиком.

Каждый шаг продлевает экран (`hvac_refresh_8_seconds`, не чаще раза в 500 мс). Если
сверху уже не `HvacActivity`, режим выключает сторожевой тик раз в 3 с. Желаемую
температуру мост держит у себя, поэтому щелчки не ждут ответа машины и не копятся;
перечитывание 16 идёт по паузе 2 с в серии. Сверка одна, через 0,6 с после последнего
щелчка: если 16 не дошла до нужной, добираем шагами 32/33 и пишем в журнал
`климат: абсолют не принят: …, шагами`. Шаги климата и громкость идут одной очередью
(`serial`), но щелчок температуры стоит теперь ~30 мс, а не 0,2…1,5 с. Кнопка и
вращение приходят в USB и BLE одновременно, копии склеиваются: кнопка 120 мс, вращение
60 мс по тому же delta.

## Почему у него есть права
Прошивка ГУ подписана **публичным тестовым ключом AOSP**: отпечаток SHA-256 `C8:A2:E9:BC:…:2A:B8` совпадает с ключом из исходников Android 9. Мост подписан тем же ключом и объявлен как `android.uid.system`, поэтому получает те же права, что и штатный экран климата. `build.sh` сам проверяет отпечаток ключа перед подписью.

Собираются `./build.sh` два варианта; оба кладутся в `bridge/apk/`, в репозитории их нет — подпись
делается ключом конкретного ГУ:
- `apk/knopych-bridge-system.apk` — основной, работает с правами системы;
- `apk/knopych-bridge-sig.apk` — запасной, без `sharedUserId`: только права по подписи. Если первый не встанет.

Переход между вариантами — только через `adb uninstall ru.knopych.bridge`.

## Команды
С Mac: `tools/kn.py <команда> [аргумент]` (см. ниже). Через adb напрямую:
```
adb shell am broadcast -a ru.knopych.bridge.CMD -n ru.knopych.bridge/.CommandReceiver --es cmd seat_driver --es arg 3
```
Из MacroDroid: действие **Send Intent** → Target: Broadcast, Action `ru.knopych.bridge.CMD`, Package `ru.knopych.bridge`, Class `ru.knopych.bridge.CommandReceiver`, Extra `cmd` (и `arg`).

| Команда | Что делает |
|---|---|
| `status` | всё прочитать: режим питания, температура, сиденья, руль, стёкла (только чтение) |
| `seat_driver 0..3`, `seat_passenger 0..3` | уровень подогрева сиденья, ставится сразу |
| `seat_memory 1..3` | вызвать сохранённый пресет положения сиденья водителя (Aptiv 155 → 4/5/6) |
| `seat_save 1..3` | сохранить текущее положение в слот (Aptiv 155 → 1/2/3), код результата — из 156; при успехе сразу вызывается слот |
| `brightness [1..10\|toggle]` | яркость экрана ГУ (Aptiv 242, 1..10); после записи перечитывает значение |
| `climate` | диагностика климата: `power_mode`, состояние экрана/кнопки энкодера, 16/17 (сырое и °C), 18, состояния функций 16/17/18 и 38/40 |
| `climate temp up` / `down` | шаг температуры **водительской зоны**: 32/33 (на пределе не шагает); при выключенном режиме «2 зоны» машина двигает обе температуры сама. Читает 16 до и после: `климат: водитель 230 (23.0C) -> 235 (23.5C) (шаг up)`. Это диагностический путь с проверкой и повтором; с ручки температура ставится абсолютным значением (`climate abs`) |
| `climate abs <°C>` | температура водителя абсолютным значением, как у штатной шкалы: `38 = °C×10`, сразу за ним `38 = −10`; читает 16 до и через 450 мс: `климат: abs 24.0 -> 38=240, -10; водитель 230 (23.0C) -> 240 (24.0C); state 38 …` |
| `climate act <id> <0\|1>` | диагностика: один `setHvacFunctionAction(id, v)` без парного отпускания — проверить одиночные id `климат: act 34=1 отправлено` |
| `climate fan up` / `down` / `1..7` | вентилятор: `up/down` — шаги 36/37; `1..7` — абсолют в 40, если машина не приняла — шагами 36/37; читает 18 до и после |
| `climate raw <id> <value>` | диагностика: прямая запись функции климата без клампов и чтения; для 16/17/18 ещё и чтение через 300 мс |
| `hvac open` / `hvac close` | открыть (`enter_hvac`) / закрыть (`sidemenu_showing`) экран климата |
| `vbtn 0\|1` | отладка ручки без панели: событие кнопки энкодера ровно как строка `vbtn` из ESP (дедуп и режим как в жизни); ответ — состояние режима |
| `vol N` | отладка ручки без панели: вращение ровно как `!vol N` из ESP; ответ — состояние режима |
| `prop 0x11200407` | прочитать произвольное VHAL-свойство по id (hex или десятичное) — диагностика: ищем сигнал датчика света |
| `park` | сколько машина стояла: `стоянка: идёт 12 мин (с 14:03), предыдущая 2 ч 5 мин` |
| `wheel on/off` | руль |
| `windshield on/off`, `rear on/off` | стёкла: читает состояние и «нажимает» только если нужно |
| `press_windshield`, `press_rear` | одно «нажатие», переключение (для отладки) |
| `auto on/off` | автосценарий (по умолчанию **выключен**) |
| `auto_threshold 5`, `auto_seat 3`, `auto_wheel on`, `auto_windshield on`, `auto_delay 10` | настройки сценария |
| `auto_bright on/off` | автояркость по ночи: день 10, ночь 1, ночь только вне 08:00–16:00 и с удержанием дня 3 мин (по умолчанию **выключена**, есть карточка в сценариях) |
| `auto_test` / `auto_test force` | прогнать сценарий сейчас (с проверкой температуры / без неё) |
| `config`, `log`, `ping`, `version` | настройки, журнал (последние 100 строк), проверка связи, версия |
| `button 1..6` | как нажатие кнопки панели ESP |
| `popup <текст>` | отладка плашки: показать текст по центру на 2,5 с поверх любого экрана |
| `popup seat 0..3` / `popup seat_pass 0..3` | плашка подогрева: ступени 1..3 (0 — ни одной), иконка сиденья, подпись «Водитель»/«Пассажир» |
| `popup wind on\|off` | плашка лобового: иконка и «Включено»/«Выключено» |
| `popup preset 1..3 \[saved\|failed\]` | плашка слотов сиденья: три кейкапа, выбранный слот оранжевый; `saved`/`failed` добавляет подпись «Слот N сохранён»/«не сохранён» |
| `popup sizes` | размеры окна плашки и детей в журнал — ловить расхождение «окно больше содержимого» |
| `long 1..4` | как удержание 1,5 с: 1–3 сохранить положение в слот, 4 — яркость ГУ в другой край |
| `wifi_adb status` | на этом ГУ не работает (оставлено для диагностики) |
| `ui_pad 170 50` | отступы экрана слева/сверху в пикселях |
| `getprop [ф]`, `settings [system/secure/global] [ф]`, `dumpsys служба [ф]`, `packages [ф]`, `intents пакет` | только чтение |
| `net`, `token` | адреса ГУ, порт, токен для Mac |
| `usb_list`, `esp`, `esp_send ping` | USB-устройства; состояние связи с ESP; послать строку в ESP |
| `ble` | состояние BLE-канала: `BLE: подключена <MAC>` / `нет MAC` / `не подключена (status=…)` |
| `ble_mac AA:BB:CC:DD:EE:FF` | MAC панели из журнала прошивки → подключиться по Bluetooth (пусто — выключить BLE) |
| `ble_scan [сек]` | поиск BLE-устройств (только чтение) |

## Установка моста

**Первый раз — с флешки, кабель не нужен** (проверено):

**Готовый APK — в [Releases](https://github.com/greadr71/knopych/releases)** (`knopych-bridge-system.apk`);
собирать из исходников не обязательно.

1. `./bridge/build.sh`, взять `bridge/apk/knopych-bridge-system.apk` (запасной — `knopych-bridge-sig.apk`).
2. APK — на флешку FAT32. Вынуть из левого USB ГУ всё остальное.
3. Инженерное меню ГУ: Настройки → «Системная информация» → ~10 раз тапнуть по **версии ПО**,
   пароль `*#4435ab`; дальше в Software information ~10 раз по **версии железа** (`gwmv3-HW11…`),
   пароль `aZ10&*+30`. Появятся пункты Function configuration, Certification support, Others.
4. Others → usb mode → **host**. Флешка в левый USB, дальше файловый менеджер ГУ ставит APK.

**Обновление — через adb по Wi-Fi.** Из приложения пакет не поставить: whitelist GWM в
`PackageInstaller`. Обновление той же флешкой через файловый менеджер **не проверялось** —
проверена только первичная установка.

ADB по Wi-Fi включается один раз за жизнь ГУ, по кабелю с ПК. Нужен кабель
**USB-A ↔ USB-A (папа-папа, с передачей данных)** — другие не заработали; с Mac не
заработало ни напрямую, ни через переходник USB-C → USB-A, поэтому нужен ПК с портом USB-A.

1. Двигатель заведён (ГУ работает долго), всё из левого USB вынуто. Если что-то было
   воткнуто — перезагрузить ГУ: держать «домик» и «mute» на руле ~15 с.
2. Инженерное меню — как выше, шаг 3.
3. Others → usb mode → **peripheral**, кабель: левый USB ГУ ↔ ПК. `adb devices` должен
   показать устройство; если `unauthorized` — разрешить на экране ГУ.
4. `adb root`, затем `adb shell setprop persist.adb.tcp.port 5555` и `adb reboot`:
   дальше порт 5555 живёт после каждой загрузки.
5. Вернуть режим для флешки и панели: Others → usb mode → **host**.
6. Дальше обновления идут по Wi-Fi: `tools/kn.py install`.

## С Mac по Wi-Fi
ГУ и Mac в одной сети (точка доступа телефона).
```bash
tools/kn.py find               # найти ГУ, запомнить адрес
tools/kn.py token 123-456      # токен с экрана «Кнопыч», блок «Отладка»
tools/kn.py status             # любая команда моста
tools/kn.py install            # обновить мост по воздуху через adb (adb по Wi-Fi — см. выше)
tools/kn.py logcat             # журнал в logs/wifi-logcat.txt
tools/kn.py snap до            # снимок настроек/свойств; нажать что-то на ГУ…
tools/kn.py snap после
tools/kn.py diff до после      # …и увидеть, что изменилось
tools/kn.py shot               # скриншот экрана ГУ в logs/shot-*.png
```

## Автосценарии

### «Подогрев в холод» (`auto on/off`)
Каждые 3 с мост читает режим питания (0 выкл, 1 ACC, 2 ON, 3 стартер).
1. Режим стал ON (или ГУ загрузилось уже в ON) → ждём `auto_delay` (10 с).
2. Проверяем стоянку: сценарий включается только если машина стояла **от 2 ч** (`PARK_HOURS`). Стоянка живёт в prefs (`park_from`, `park_last`), переживает сон и перезагрузку ГУ; время неизвестно — не блокируем. `park` показывает, сколько мост насчитал.
3. Читаем температуру за бортом. Если она ниже порога (5 °C) → сиденье водителя на 3, руль, лобовое.
4. Если лобовое недоступно (`state=21` — двигатель не запущен), не нажимаем, а ждём события от машины: как станет доступно — включаем. Нажатие не чаще раза в 30 с, проверка раз в минуту, сброс при OFF/ACC. Причину пишем в журнал.
5. Один раз за поездку. Новая поездка начинается после OFF/ACC.

Не проверено: ON и работающий двигатель мост не различает, так что при одном зажигании
без запуска сценарий тоже сработает. Смотрим журнал в машине.

### «Тема при включении» (`auto_theme on/off`, `auto_theme_id 1..4`)
Один раз за поездку, как только ГУ в ACC/ON, ставит тему (по умолчанию 4), если стоит другая. Ручную смену посреди поездки не перебивает, сбрасывается при OFF. Если служба тем ещё не поднялась — до 5 попыток раз в 10 с.

## Рассылка состояния
При изменениях и раз в минуту мост шлёт broadcast `ru.knopych.bridge.STATE` с extras: `outside_temp` (float), `power_mode`, `seat_driver`, `seat_passenger`, `wheel`, `windshield`, `rear`. MacroDroid ловит его триггером **Intent Received**.

## Плашка
Окно поверх любого экрана на 2,5 с: подогрев — три ступени, иконка сиденья и подпись, лобовое — иконка и состояние, слоты сиденья — три кейкапа в ряд, выбранный подсвечен. Включённое — оранжевое (#FF9A4D), выключенное — притушенное (альфа 40 %).

Своё окно `TYPE_APPLICATION_OVERLAY`, не фокусируемое, без затемнения, тапа не перехватывает: нижний экран (климат, навигация) не перерисовывается и не уходит в паузу. Окно одно и живёт между показами: смена уровня перерисовывает ступени в нём же.

Рамка берётся на ходу из **установленной темы ГУ**: `volume_adjust_frame` пакета скина (через `getResourcesForApplication` по `app_…`/`def_aptiv_config_current_theme_package_name`) режется на 9 частей (поля 20 px, тянется только середина), при смене темы фон обновляется к следующему показу. **Вшитой базовой рамки в репозитории нет** — `plaque_frame.9.png` это ресурс темы ГУ, поэтому в публичную выкладку он не входит. Если скина нет или рамки в нём нет (тема 1), плашка рисует простую подложку через `GradientDrawable`: чёрный фон, скругление, светлая обводка.

### Как добавить свою плашку
Пример — подогревы (`showSeat`, `showWindshield`). Порядок:

1. **Иконка.** SVG → векторный drawable `bridge/res/drawable/kc_<имя>.xml`. В `android:width/height` держи пропорции viewBox (например viewBox 150×128 → width 150dp/height 128dp), иначе VectorDrawable сплющит картинку под размер view.
2. **Показ.** Метод в `Plaque.java` по образцу `showSeat`/`showWindshield`: `icon(...)` задаёт размеры в px, `caption(...)` — подпись. Цвета: включено — `ACCENT`, выключено — тот же цвет с `setAlpha(0.4f)`.
3. **Команда.** Ветка в `Bridge.java` в `case "popup"`, и дополнить `HELP` (иначе команду не найти).
4. **Проверка.** `bridge/build.sh` → `tools/kn.py install` → `popup <команда>` → `popup sizes` (числа окна и детей в журнал) → `tools/kn.py shot` (скриншот с ГУ).

## Откуда взяты API
- Подключение — как в `com.gwmv3.vehicle` `VehicleApplication.connectCarHelper()`: `new AndroidCarClient(ctx, null)`, `new AptivCarClient(ctx, null)`, затем `new AptivCarSettingFunction(a, b).initFunction()` и `new AptivCarHvacFunction(a, b).initFunction()`.
- Сигнатуры классов сняты с `aptiv.support.car.vdex` (compact-dex) своим парсером. Заглушки для компиляции лежат в `stubs/`, в APK они не попадают.
- Константы: сиденья 64/65, руль 149, лобовое 12, заднее 11, `FUNCTION_POWER_MODE` 15, `APTIV_OUTSIDE_TEMPERATURE` 0x21402039 (сырое 0–255, пересчёт делает `AptivCarHvac.getOutsideTemp()`).
- Стандартное `ENV_OUTSIDE_TEMPERATURE` — заглушка (всегда 25.0), им не пользуемся.
