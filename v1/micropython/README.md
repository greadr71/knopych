# Прошивка панели «Кнопыч» на MicroPython (ESP32-S3)

Альтернатива [Arduino-версии](../../docs/firmware.md). Кнопки и светодиоды работают так же. Связь с Mac и (позже) с ГУ — **по USB**, текстовыми строками. Bluetooth в коде есть (протокол как у Arduino-версии), но выключен: на этой плате радио роняет питание (см. ниже).

Код: [main.py](main.py). Слушатель для Mac: [panel_usb.py](panel_usb.py). Железо — [../../docs/hardware.md](../../docs/hardware.md), распиновка — [../docs/pins.md](../docs/pins.md).

## Проверено на плате (2026-11-07, v0.3-mpy)
- Кнопка 1 (GPIO4) и светодиод 1 (GPIO17): ступени 3 → 2 → 1 → выкл, яркость меняется.
- USB-протокол: `ping`, `leds`, `state`, `local`, нажатия приходят на Mac.
- Остальные 5 кнопок и светодиодов пока не подключены.

## Чем удобнее Arduino
- Ничего не нужно компилировать: правишь `main.py`, заливаешь за пару секунд.
- Можно запустить код с Mac, не записывая его на плату (`run`).
- Есть консоль (REPL): можно руками зажечь светодиод или прочитать кнопку, например `from machine import Pin; Pin(17, Pin.OUT).on()`.

## Что нужно на Mac
- `esptool`, `mpremote`, `pyserial`: `pip install esptool mpremote pyserial` (на этом ноуте уже есть, в miniforge).
- Образ MicroPython для ESP32-S3: обычный `ESP32_GENERIC_S3` (без `SPIRAM_OCT`: у модуля N8R2 PSRAM не «octal»). Скрипт сам скачает его в `download/` (в git не попадает).

## Как прошить и пользоваться
Один раз — записать сам MicroPython (стирает всё, что было на плате, в том числе Arduino-прошивку):
```bash
v1/micropython/flash.sh install
```
Если плата не переходит в режим прошивки: зажать **BOOT**, нажать **RST**, отпустить BOOT и повторить. Если после записи плата молчит, она осталась в режиме прошивки — нажать **RST**.

Дальше:
```bash
v1/micropython/flash.sh listen        # нажатия на Mac; можно печатать команды (см. ниже)
v1/micropython/flash.sh listen --gu   # Mac изображает ГУ: сам решает ступень и шлёт её в светодиоды
v1/micropython/flash.sh upload        # залить main.py после правки и перезапустить плату
v1/micropython/flash.sh repl          # журнал и REPL; Ctrl+C — остановить программу; Ctrl+X — выход
v1/micropython/flash.sh run           # запустить main.py с Mac без записи на плату (для проб)
```
Другой порт: `PORT=/dev/cu.xxx v1/micropython/flash.sh listen`.

Вернуться на Arduino-версию можно в любой момент: `./build.sh upload` перезапишет плату.

## USB-протокол
Обычный последовательный порт (115200, хотя для USB скорость не важна), строки текста, конец строки `\n`. Работает через **оба** разъёма платы.

Плата → Mac/ГУ. Строки протокола начинаются с `!`, остальное — журнал для человека (`[ble] …`, сообщения загрузчика), его можно пропускать.

| Строка | Когда |
|---|---|
| `!hello knopych v0.3-mpy` | плата запустилась |
| `!btn N` | нажата кнопка N (1..6) |
| `!leds a b c d e f` | ступени светодиодов изменились (или ответ на `leds` / `state`) |
| `!mode local` / `!mode remote` | ответ на `local` / `state` |
| `!pong knopych v0.3-mpy` | ответ на `ping` |
| `!err …` | непонятная команда |

Mac/ГУ → плата:

| Команда | Что делает |
|---|---|
| `leds 3 1 0 0 0 0` | ступени светодиодов 0..3 (для вкл/выкл 0/1, больше обрезается). Можно меньше 6 чисел — остальные без изменений. Переводит плату в режим **remote** |
| `local` | вернуть режим **local**: нажатие само меняет свой светодиод |
| `state` | прислать `!leds …` и `!mode …` |
| `ping` | прислать `!pong …` |

Режимы:
- **local** (по умолчанию, после включения): нажатие шлёт `!btn N` и само меняет ступень своего светодиода.
- **remote** (после первой `leds`): нажатие только шлёт `!btn N`, светодиоды показывают то, что прислали. Так ГУ сможет показывать **реальное** состояние подогревов. Мосту на ГУ при отключении надо слать `local`; при перезагрузке платы режим и так сбрасывается.

Байт `0x03` (Ctrl+C) не слать: он останавливает программу на плате.

### Подводные камни разъёмов
- Разъём **USB** (родной USB ESP, `/dev/cu.usbmodem101`): порт пропадает при каждой перезагрузке платы.
- Разъём **COM/UART** (мост WCH, `USB Single Serial`, `/dev/cu.usbmodem5B5F…`): порт не пропадает, видно сообщения загрузчика (`rst:…`, `Brownout`) — для отладки он. Но **открытие порта перезагружает плату** (линии DTR/RTS) — поэтому слушатель ждёт `!hello`.
- Для ГУ, скорее всего, лучше родной **USB**: это стандартный CDC-порт, Android умеет с ним работать без особых драйверов (библиотека usb-serial-for-android). Не проверено.

## Bluetooth и просадка питания
На плате из прототипа включение BLE роняет питание: в журнале `E BOD: Brownout detector was triggered` или `rst:0x1 (POWERON)` сразу после `b.active(True)` (2026-11-07, питание от Mac, оба USB-разъёма платы). С Wi-Fi было то же самое — радио при старте берёт пиковый ток, питание платы его не держит. Код тут ни при чём.

Поэтому `USE_BLE = False` в начале `main.py`. Если включить (`True`), сработает защита: перед включением BLE на флешку пишется файл `ble_try` и стирается через 3 с работы. Если плата перезагрузилась раньше, при следующем старте BLE не включается, кнопки и USB работают, встроенный RGB горит **красным**. Следующее включение питания снова пробует BLE.

Что попробовать для BLE: питание от зарядки телефона вместо Mac, короткий толстый кабель без хаба, конденсатор 470–1000 мкФ между 5V и GND, другая плата.

Цвета встроенного RGB:
- только USB (`USE_BLE = False`): **зелёный** — светодиодами управляет Mac/ГУ (remote), не горит — local;
- с BLE: мигает **синим** — ждёт подключения, **зелёный** — подключено, **красный** — BLE выключен из-за питания.

## Отличия от Arduino-версии
- **Причина перезагрузки:** MicroPython не отличает просадку питания (`BROWNOUT`) от обычного включения; полную причину видно в журнале загрузчика через разъём COM/UART.
- **Wi-Fi:** MicroPython сам Wi-Fi не включает, модуль `network` в коде не используется. Не включать его и в REPL — плата уйдёт в перезагрузку.

## Не проверено
- Связь с ГУ по USB: даст ли ГУ приложению доступ к USB-порту платы.
- BLE на плате: не хватает питания (см. выше).
- На каком GPIO встроенный RGB (48 или 38) — константа `RGB_PIN` в начале `main.py`.
