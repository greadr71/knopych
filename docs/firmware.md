# Протокол панели «Кнопыч» (ESP32-S3-Zero)

Панель — 6 кнопок, 6 светодиодов и энкодер громкости на Waveshare ESP32-S3-Zero.
Связь с Mac/ГУ — текстовые строки по USB (нативный USB-Serial/JTAG) и те же строки в Bluetooth LE.

Реализаций две, протокол у них общий:

| Версия | Плата/жгут | Скетч | Пины |
|---|---|---|---|
| **v0.8** (текущая) | печатная панель, [v2](../v2/) | [v2/firmware/knopych-panel.ino](../v2/firmware/knopych-panel/knopych-panel.ino) | [v2/docs/pins.md](../v2/docs/pins.md) |
| v0.6 (архив) | макетка, [v1](../v1/) | [v1/firmware/knopych-panel.ino](../v1/firmware/knopych-panel/knopych-panel.ino) | [v1/docs/pins.md](../v1/docs/pins.md) |

Есть и [MicroPython-версия](../v1/micropython/README.md) с тем же USB-протоколом.
Железо — [hardware.md](hardware.md); история перехода на новую плату — в архиве.

## Что умеет (v0.8)

| № | Кнопка (GPIO) | Светодиод (GPIO) | Что делает | Ступени |
|---|---|---|---|---|
| 1 | 1 | — (не припаян, пин 3 свободен) | пресет положения сиденья 1 | 0 ↔ 1 |
| 2 | 2 | — (8) | пресет 2 | 0 ↔ 1 |
| 3 | 4 | — (43) | пресет 3 | 0 ↔ 1 |
| 4 | 7 | 44 (RX) | подогрев водителя | 0 → 3 → 2 → 1 → 0 |
| 5 | 6 | 12 | лобовое | 0 ↔ 1 |
| 6 | 5 | 11 | подогрев пассажира | 0 → 3 → 2 → 1 → 0 |

- **Яркость** ступени 0..3 — `BRIGHT = {0, 6, 40, 255}`; у кнопок с двумя ступенями включение сразу на полную (255).
  Светодиоды 1–3 в прошивке есть (пины 3, 8, 43), но физически не припаяны: какой слот активен, на панели не видно.
- **Опрос** каждые 5 мс, нажатие засчитывается после 50 мс стабильного `LOW`, подтяжка внутренняя (`INPUT_PULLUP`), нажата = `LOW`.
- **Удержание 1,5 с** (`HOLD_MS`) только у кнопок 1–4: у 1–3 — сохранить текущее положение сиденья в слот (делает Mac/ГУ),
  у 4 — яркость экрана ГУ в другой край. У этих кнопок `!btn N` уходит на отпускании (если держали меньше 1,5 с),
  у 5 и 6 — сразу по нажатию.
- **Энкодер** громкости ALPS EC11E15244G1: A → GPIO9, B → GPIO10, C → GND; кнопка D → GPIO13, E → GND.
  Один щелчок = 2 перехода квадратуры (`ENC_TRANSITIONS_PER_DETENT`) → событие `vol 1` / `vol -1`.
  Направление меняется `#define ENC_INVERT 1` без перепайки. Кнопка энкодера шлёт `vbtn 1` на нажатие и
  `vbtn 0` на отпускание (дребезг 20 мс).
- **Bluetooth LE** включён (`#define USE_BLE 1`), имя `Knopych`. Без него панель работает только по USB.
- **Режимы:** `local` (по умолчанию) — нажатие само меняет ступень своего светодиода;
  `remote` — светодиоды показывают только то, что прислал Mac/ГУ.
- **Встроенный WS2812** (GPIO21, яркость 20/255): без BLE — зелёный в remote, погашен в local;
  с BLE — зелёный при подключённом клиенте, синий мигает, пока клиента нет.
- **Wi-Fi не включается никогда** (`WiFi.h` не подключается).
- При старте — прогон всех светодиодов по очереди, причина последней перезагрузки в журнале.

## USB-протокол

Порт 115200, строки текста, конец строки `\n`. Открытие порта плату не перезагружает.
Строки протокола начинаются с `!`, остальное — журнал для человека, его можно пропускать.

### Плата → Mac/ГУ

| Строка | Когда | Что делает мост |
|---|---|---|
| `!hello knopych v0.8` | после старта | запоминает версию, сбрасывает кэш и шлёт `leds` заново |
| `!leds 1 0 0 2 0 3` | ступени изменились, ответ на `leds` / `state`, после записи в BLE | не разбирает (сам знает, что отправил) |
| `!btn N` | кнопка N (1..6): 5, 6 — по нажатию, 1–4 — по отпусканию раньше 1,5 с | действие кнопки N в машине |
| `!long N` | кнопка N (1..4) удержана 1,5 с | 1–3 — сохранить положение в слот, 4 — яркость ГУ |
| `!vol 1` / `!vol -1` | щелчок энкодера | шаг громкости; если открыт экран климата — уставка/вентилятор |
| `!vbtn 1` / `!vbtn 0` | кнопка энкодера нажата / отпущена | открыть/закрыть экран климата |
| `!pong knopych v0.8` | ответ на `ping` | версия |
| `!mode local` / `!mode remote` | ответ на `local` / `state` | — |
| `!err unknown: <строка>` | неизвестная команда | журнал |
| `!err leds: нужны числа 0..3, …` | в `leds` не числа | журнал |

Каждое событие кнопки/энкодера уходит сразу в два канала — USB и BLE (notify). Мост дедуплицирует
одинаковые `btn`/`long` по времени.

### Mac/ГУ → плата

| Команда | Что делает |
|---|---|
| `leds 3 1 0 0 0 0` | ступени светодиодов 0..3, лишнее обрезается по максимуму кнопки, отрицательное — в 0. Можно меньше 6 чисел — остальные без изменений. Переводит в **remote** и отвечает `!leds` |
| `local` | вернуть **local**, отвечает `!mode local` |
| `state` | `!leds …` и `!mode …` |
| `ping` | `!pong knopych v0.8` |

Режимы: после включения всегда **local**; первая `leds` (или запись в BLE) включает **remote**.
При обрыве BLE прошивка сама возвращается в local и сбрасывает ступени в 0; при остановке моста
мост сам шлёт `local`.

## Чем v0.6 отличается

| | v0.6 (макетка) | v0.8 (печатная панель) |
|---|---|---|
| Кнопки | 1, 2, 4, 5, 6, 7 | 1, 2, 4, **7**, **6**, **5** (4 и 6 поменялись местами) |
| Светодиоды | 8, 9, 10, 11, 12, 44 (все припаяны) | **3, 8, 43** (не припаяны), 44, 12, 11 |
| Энкодер A/B | 13 / 43 | 9 / 10 |
| Кнопка энкодера | не подключена | GPIO13, события `vbtn` |

`vol 1` / `vol -1` есть в обеих версиях, `vbtn` — только в v0.8. Остальное (ступени, удержание, режимы,
BLE-сервис, строки протокола) одинаковое; в v0.6 в `!hello`/`!pong` стоит `v0.6`.

## BLE

Панель рекламирует сервис и имя `Knopych`, в рекламе отдаёт ещё и scan response. MAC печатается
в журнал при старте (`[ble] MAC … advertising as Knopych`) — мост прописывается на него командой
`ble_mac AA:BB:CC:DD:EE:FF` (пусто — BLE выключен). MAC у каждой платы свой, в документах его не храним.

| Характеристика | UUID | Свойства | Формат |
|---|---|---|---|
| BUTTONS | `6d656368-6275-7474-0002-000000000000` | read, notify | та же строка, что ушла по USB: `btn N`, `long N`, `vol ±1`, `vbtn 0/1` |
| LEDS | `6d656368-6275-7474-0003-000000000000` | read, write | до 6 байт ступеней 0..3, как `leds`; запись включает remote |

- Сервис: `6d656368-6275-7474-0001-000000000000` (в ASCII — прежнее имя).
- Для BUTTONS мосту нужно включить notify через CCCD (`BLE2902`); без дескриптора он считает канал мёртвым.
- LEDS только read/write, без notify: ступени мост присылает сам.
- После разрыва панель сбрасывает ступени в 0, возвращается в local и через 200 мс снова рекламируется.
- Проверка без моста: **nRF Connect** → `Knopych` → у BUTTONS включить уведомления, в LEDS записать hex
  `030100000000`.

## Сборка и прошивка (Mac)

Один раз: `brew install arduino-cli`, добавить URL пакета ESP32 (`https://espressif.github.io/arduino-esp32/package_esp32_index.json`),
`arduino-cli core install esp32:esp32` (~1–1,5 ГБ).

```bash
./build.sh                                        # собрать v2/firmware/knopych-panel
./build.sh upload                                 # собрать и прошить (порт ищется сам)
./build.sh monitor                                # журнал, Ctrl+C — выход
./build.sh listen                                 # нажатия на Mac (pyserial), --gu — изображать ГУ
SKETCH=v1/firmware/knopych-panel ./build.sh upload   # старая панель
SKETCH=v2/firmware/pin-scan ./build.sh upload         # проверка пинов
```

`build.sh` подставляет FQBN сам:
`esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=default,PSRAM=disabled`
(4 МБ флеш, USB CDC включён, PSRAM выключен — `default_4MB` в ядре нет).
Порт — первый из `/dev/cu.usbmodem*`, `/dev/cu.usbserial*`, `/dev/cu.wchusbserial*`; другой задаётся `PORT=/dev/cu.xxx`.
Если прошивка не стартует: зажать **BOOT**, нажать **RST**, отпустить BOOT, повторить `upload`.

## Проверено / не проверено

Проверено:
- BLE-линк на ГУ (15.11): мост подключается по MAC, notify включается, `leds` идёт и в USB, и в BLE;
  нажатие кнопки по BLE при выдернутом USB доходит (светодиоды показывают реальное состояние).
- Громкость на ГУ: мост меняет группу MUSIC машины, команда `volume 2→5→2` совпала с `dumpsys car_service`.
- Старый жгут (v0.6), машина 18.11: все 6 кнопок, удержание 1,5 с, светодиоды по реальному состоянию,
  сохранение слота удержанием, пресеты сиденья.

Не проверено:
- v0.8 на новом жгуте в машине: кнопки 4/6 на GPIO7/5, светодиоды 44/11, энкодер 9/10, кнопка 13.
- Живой энкодер: щелчки `vol` и `vbtn` из машины ещё не шли, громкость проверена только командой `volume`.
