# Протокол панели «Кнопыч» (ESP32-S3-Zero)

Панель — 6 кнопок и энкодер громкости на Waveshare ESP32-S3-Zero. Светодиодов кнопок
в проекте нет: обратную связь показывает экран ГУ плашками.
Связь с Mac/ГУ — текстовые строки по USB (нативный USB-Serial/JTAG) и те же строки в Bluetooth LE.

Реализаций две: у v1.0 (текущая) и v0.6 (архив) общий протокол кнопок и энкодера.
LED-команды (`leds`, `local`, `state`) и BLE-характеристика LEDS остались только в архиве.

| Версия | Плата/жгут | Скетч | Пины |
|---|---|---|---|
| **v1.0** (текущая) | печатная панель, [v2](../v2/) | [v2/firmware/knopych-panel.ino](../v2/firmware/knopych-panel/knopych-panel.ino) | [v2/docs/pins.md](../v2/docs/pins.md) |
| v0.6 (архив) | макетка, [v1](../v1/) | [v1/firmware/knopych-panel.ino](../v1/firmware/knopych-panel/knopych-panel.ino) | [v1/docs/pins.md](../v1/docs/pins.md) |

Есть и [MicroPython-версия](../v1/micropython/README.md) — архив, протокол v0.6 с LED-командами.

## Что умеет (v1.0)

| № | Кнопка (GPIO) | Что делает |
|---|---|---|
| 1 | 1 | пресет положения сиденья 1 |
| 2 | 2 | пресет 2 |
| 3 | 4 | пресет 3 |
| 4 | 7 | подогрев водителя |
| 5 | 6 | лобовое |
| 6 | 5 | подогрев пассажира |

- **Кнопки только шлют события** — `!btn N` (и `!long N` на удержании). Ступени подогревов,
  занятость слотов и всё остальное состояние хранит мост на ГУ, он же показывает плашку.
- **Опрос** каждые 5 мс, нажатие засчитывается после 50 мс стабильного `LOW`, подтяжка внутренняя (`INPUT_PULLUP`), нажата = `LOW`.
- **Удержание 1,5 с** (`HOLD_MS`) только у кнопок 1–4: у 1–3 — сохранить текущее положение сиденья в слот (делает Mac/ГУ),
  у 4 — яркость экрана ГУ в другой край. У этих кнопок `!btn N` уходит на отпускании (если держали меньше 1,5 с),
  у 5 и 6 — сразу по нажатию.
- **Энкодер** громкости ALPS EC11E15244G1: A → GPIO9, B → GPIO10, C → GND; кнопка D → GPIO13, E → GND.
  Один щелчок = 2 перехода квадратуры (`ENC_TRANSITIONS_PER_DETENT`) → событие `vol 1` / `vol -1`.
  Направление меняется `#define ENC_INVERT 1` без перепайки. Кнопка энкодера шлёт `vbtn 1` на нажатие и
  `vbtn 0` на отпускание (дребезг 20 мс).
- **Bluetooth LE** включён (`#define USE_BLE 1`), имя `Knopych`. Без него панель работает только по USB.
- **Встроенный WS2812** (GPIO21, яркость 20/255) — короткий индикатор связи, постоянного свечения нет:
  после подключения BLE зелёный 3 с и гаснет; пока идёт реклама, синий мигает 0,5/0,5 с, но только
  первые 60 с после старта или разрыва, потом гаснет; в USB-only погашен.
- **Пины бывших светодиодов** (11, 12, 44) прошивка не настраивает: они остаются входами, чтобы
  припаянные на собранной панели светодиоды не светились. 43/44 — UART0, журнал идёт через USB CDC.
- **Wi-Fi не включается никогда** (`WiFi.h` не подключается).
- При старте — версия и причина последней перезагрузки в журнале, прогона светодиодов нет.

## USB-протокол

Порт 115200, строки текста, конец строки `\n`. Открытие порта плату не перезагружает.
Строки протокола начинаются с `!`, остальное — журнал для человека, его можно пропускать.

### Плата → Mac/ГУ

| Строка | Когда | Что делает мост |
|---|---|---|
| `!hello knopych v1.0` | после старта | запоминает версию |
| `!btn N` | кнопка N (1..6): 5, 6 — по нажатию, 1–4 — по отпусканию раньше 1,5 с | действие кнопки N в машине |
| `!long N` | кнопка N (1..4) удержана 1,5 с | 1–3 — сохранить положение в слот, 4 — яркость ГУ |
| `!vol 1` / `!vol -1` | щелчок энкодера | шаг громкости; если открыт экран климата — уставка/вентилятор |
| `!vbtn 1` / `!vbtn 0` | кнопка энкодера нажата / отпущена | открыть/закрыть экран климата |
| `!pong knopych v1.0` | ответ на `ping` | версия |
| `!err unknown: <строка>` | неизвестная команда | журнал |

Каждое событие кнопки/энкодера уходит сразу в два канала — USB и BLE (notify). Мост дедуплицирует
одинаковые `btn`/`long` по времени.

### Mac/ГУ → плата

| Команда | Что делает |
|---|---|
| `ping` | `!pong knopych v1.0` |

Больше команд нет: прошивка ничего не запоминает и не показывает. `leds`, `local`, `state` — только в архиве v0.6.

## Чем v0.6 отличается

| | v0.6 (макетка, архив) | v1.0 (печатная панель) |
|---|---|---|
| Кнопки | 1, 2, 4, 5, 6, 7 | 1, 2, 4, **7**, **6**, **5** (4 и 6 поменялись местами) |
| Светодиоды | 8, 9, 10, 11, 12, 44 (все припаяны) | нет: пины 3, 8, 11, 12, 43, 44 свободны |
| Энкодер A/B | 13 / 43 | 9 / 10 |
| Кнопка энкодера | не подключена | GPIO13, события `vbtn` |
| LED-команды и BLE LEDS | есть (`leds`, `local`, `state`, запись ступеней) | нет |

`vol 1` / `vol -1` есть в обеих версиях, `vbtn` — только в v1.0. Обратная связь в v1.0 — плашка на
экране ГУ; в v0.6 в `!hello`/`!pong` стоит `v0.6`.

## BLE

Панель рекламирует сервис и имя `Knopych`, в рекламе отдаёт ещё и scan response. MAC печатается
в журнал при старте (`[ble] MAC … advertising as Knopych`) — мост прописывается на него командой
`ble_mac AA:BB:CC:DD:EE:FF` (пусто — BLE выключен). MAC у каждой платы свой, в документах его не храним.

| Характеристика | UUID | Свойства | Формат |
|---|---|---|---|
| BUTTONS | `6d656368-6275-7474-0002-000000000000` | read, notify | та же строка, что ушла по USB: `btn N`, `long N`, `vol ±1`, `vbtn 0/1` |

- Сервис: `6d656368-6275-7474-0001-000000000000` (задан исторически, не менять).
- Характеристика одна: второй (LEDS) в v1.0 нет. Мосту достаточно BUTTONS, включать notify через CCCD (`BLE2902`).
- После разрыва панель через 200 мс снова рекламируется; сбрасывать нечего — состояния в прошивке нет.
- Проверка без моста: **nRF Connect** → `Knopych` → у BUTTONS включить уведомления и нажимать кнопки.

## Сборка и прошивка (Mac)

Один раз: `brew install arduino-cli` и ядро ESP32 версии 3.x (~1–1,5 ГБ):

```bash
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.12
```

На ядре 2.x скетч не собирается: нужны `rgbLedWrite` и BLE-колбэк с `ble_gap_conn_desc` из NimBLE.

```bash
./build.sh                                        # собрать v2/firmware/knopych-panel
./build.sh upload                                 # собрать и прошить (порт ищется сам)
./build.sh monitor                                # журнал, Ctrl+C — выход
./build.sh listen                                 # нажатия на Mac (pyserial), --gu — изображать ГУ
SKETCH=v1/firmware/knopych-panel ./build.sh upload   # старая панель (архив)
SKETCH=v2/firmware/pin-scan ./build.sh upload         # проверка пинов
```

`build.sh` подставляет FQBN сам:
`esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=default,PSRAM=disabled`
(4 МБ флеш, USB CDC включён, PSRAM выключен; схема разделов `default` — варианта `default_4MB` в ядре нет).
Порт — первый из `/dev/cu.usbmodem*`, `/dev/cu.usbserial*`, `/dev/cu.wchusbserial*`; другой задаётся `PORT=/dev/cu.xxx`.
Если прошивка не стартует: зажать **BOOT**, нажать **RST**, отпустить BOOT, повторить `upload`.

## Проверено / не проверено

Проверено:
- BLE-линк на ГУ (15.11, прошивка v0.8): мост подключается по MAC, notify включается, нажатие
  кнопки по BLE при выдернутом USB доходит.
- Громкость на ГУ: мост меняет группу MUSIC машины, команда `volume 2→5→2` совпала с `dumpsys car_service`.
- Старый жгут (v0.6), машина 18.11: все 6 кнопок, удержание 1,5 с, сохранение слота удержанием, пресеты.

Не проверено:
- v1.0 на новом жгуте в машине: кнопки 4/6 на GPIO7/5, энкодер 9/10, кнопка 13 и тайминги
  индикатора связи (зелёный 3 с, синее мигание 60 с).
- Совместимость по BLE: новый APK v0.49 работает и со старой прошивкой v0.8; старый APK v0.48
  с прошивкой v1.0 по BLE не соединится — он ищет характеристику LEDS, которой больше нет.
