# Интерфейс ГУ, которым пользуется мост

Мост «Кнопыч» работает внутри штатного головного устройства Haval Dargo (Android 9,
прошивка Aptiv). Здесь — минимум, без которого его не собрать: как получить права и
какие вызовы соответствуют кнопкам климата.

> Материал получен изучением своего устройства для обеспечения совместимости
> (ст. 1280 ГК РФ; в ЕС — ст. 6 Директивы 2009/24/EC). Код правообладателя здесь не
> воспроизводится: только имена, идентификаторы и наблюдаемое поведение.
> Haval, Dargo, GWM, Aptiv — товарные знаки правообладателей; проект с ними не связан.

## Права

Автомобильный API закрыт разрешениями уровня `signature|privileged`
(`android.car.permission.CAR_VENDOR_EXTENSION` и climate-разрешения). Обычному
приложению их не выдать — ни пользователем, ни runtime-грантом через adb.

Прошивка этого ГУ собрана на **публичных тестовых ключах AOSP** (`test-keys`). Значит
APK, подписанный тем же платформенным ключом, совпадает по подписи с системными
приложениями и получает разрешения `signature`. Защиту это не обходит: устройство само
принимает такую подпись, ключ лежит в открытом дереве AOSP.

```bash
# bridge/build.sh скачивает их сам и сверяет отпечаток
platform.pk8, platform.x509.pem  ← build/make/target/product/security (AOSP, Apache-2.0)
```

На ГУ с обычными (не тестовыми) ключами способ не работает — другого пути получить эти
разрешения у проекта нет.

## Сиденья и руль — значение напрямую

Класс `aptiv.support.car.AptivCarSettingFunction`:

```java
void setVehicleFunctionValue(int functionId, int value);
int  getVehicleFunctionValue(int functionId);   // бросает CarNotConnectedException
```

| Функция | id | Значения |
|---|---|---|
| Подогрев сиденья водителя | `0x40` (64) | 0–3, 0 = выкл |
| Подогрев сиденья пассажира | `0x41` (65) | 0–3 |
| Подогрев руля | `0x95` (149) | 0 / 1 |
| Слоты памяти сиденья | `155` | чтение — активный слот, запись N — сохранить текущее положение |

Уровень ставится значением: `setVehicleFunctionValue(64, 2)` — второй уровень.

## Стёкла: переключатель, а не значение

Класс `aptiv.support.car.AptivCarHvacFunction`:

```java
void setHvacFunctionAction(int id, int action);   // action 1, сразу следом 0
```

| Функция | id | Состояние |
|---|---|---|
| Лобовое стекло | `0x0c` (12) | `getFrontWindshieldHeatOnOffState()` |
| Заднее стекло | `0x0b` (11) | `getRearDefrosterState()` |

Это переключатель: каждое «нажатие» меняет состояние на противоположное. Поэтому мост
сначала читает состояние и «нажимает», только если нужно другое.

Стандартное свойство `HVAC_DEFROSTER` к электрообогреву стёкол отношения не имеет и
всегда `false`.

## Громкость

`aptiv.support.car.AptivCarAudio.setGroupVolume(GROUP_MUSIC, 0..39)` — группа MUSIC
машины. `AudioManager.setStreamVolume` на реальную громкость не влияет (проверено).

## Экран климата

Штатный экран климата открывается broadcast-ом `com.gwmv3.vehicle.enter_hvac`.
Мост делает это по нажатию энкодера и продлевает тайм-аут экрана, пока крутят ручку.

## Тема

Темы ставит системная служба `com.aptiv.thememanager`; мост вызывает её от имени
системы. Темы: 1–4 (id 8 недоступна).

Записать тему 4 мало: SystemUI разносит пакет темы по своему ключу, и после записи
нужно дождаться, пока совпадут оба значения в `settings system`:
`def_aptiv_config_current_theme_package_name` и
`app_aptiv_config_current_theme_package_name`. Мост повторяет запись раз в минуту,
пока они не совпадут (команда `theme N`, проверено 1 → 4 → 1).

## Яркость и день/ночь

- Яркость ГУ — 1..10, ставится через мост (`brightness N`).
- **Датчика освещённости в машине нет.** Единственный доступный признак — решение
  автосвета `AptivCarVariable.getDayNightMode()` (день/ночь). Оно дребезжит: в
  пасмурный день десятки переключений за полчаса. Поэтому автояркость в мосте
  работает по окну времени (08:00–16:00 — всегда день) и с гистерезисом: в ночь —
  сразу, обратно в день — после 3 минут стабильного «день».
- Свойство `NIGHT_MODE` в этой прошивке мёртвое (всегда 0, событий нет) — не
  использовать.

## Чего мост не трогает

Только комфорт: подогревы, климат, громкость, яркость, тема. Тормоза, руль (управление),
подушки, иммобилайзер, движение — вне проекта; CAN-шина машины панели не нужна.
